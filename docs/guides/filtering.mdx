# Filtering Lists

Activities, subjects, sessions and subject groups are all listed the same way: `list(...)` takes the filters you want and returns a sequence you iterate directly.

Every sequence also carries `total`, the number of matching items, and `all()`, which collects the rest into an array.

## Activities

<Tabs groupId="language">
  <TabItem value="swift" label="Swift">
  ```swift
  let activities = client.activities.list(search: "squat", onlyCompleted: true)

  for try await activity in activities {
      print(activity.name ?? activity.id, activity.status)
  }
  ```
  </TabItem>
  <TabItem value="ts" label="TypeScript">
  ```typescript
  const activities = client.activities.list({ search: "squat", onlyCompleted: true });

  for await (const activity of activities) {
    console.log(activity.name, activity.status);
  }
  ```
  </TabItem>
  <TabItem value="python" label="Python">
  ```python
  activities = client.activities.list(search="squat", only_completed=True)

  for activity in activities:
      print(activity.name, activity.status)
  ```
  </TabItem>
</Tabs>

Calibration and neutral-pose activities are left out by default. Pass `excludeCalibration: false` to include them.

| Filter | Selects |
|---|---|
| `subject` | Activities recorded for one subject |
| `calibrationSession` | Activities recorded under one calibration session |
| `activityType` | Activities of one type — see [Activity Types](#activity-types) |
| `excludeCalibration` | Whether to leave out calibration and neutral-pose activities (default `true`) |
| `createdAfter` / `createdBefore` | An inclusive date range |
| `search` | Free-text match against the activity name |
| `tags` | Activities carrying every tag in the list |
| `createdBy` | Activities belonging to one or more account ids |
| `onlyCompleted` | Activities whose recording finished |
| `excludeAnalysisError` | Leaves out activities whose analysis failed |

| Filter | Selects |
|---|---|
| `search` | Free-text match against the subject name |
| `createdAfter` / `createdBefore` | An inclusive date range |
| `groups` | Subjects belonging to one of these subject groups |
| `tags` | Subjects carrying every tag in the list |
| `createdBy` | Subjects belonging to one or more account ids |
| `activityType` | Subjects with an activity of this type — see [Activity Types](#activity-types) |
| `activityComplete` | Subjects with at least one completed activity |
| `session` | Subjects recorded in one session |

## Activity Types

The types available are the account's own: the ones everybody has, plus any the account or its organisation added. Read them, then filter by one.

<Tabs groupId="language">
  <TabItem value="swift" label="Swift">
  ```swift
  let types = try await client.activityTypes()
  let squats = types.first { $0.displayName == "Squat Exercise" }!

  for try await activity in client.activities.list(activityType: squats) {
      print(activity.name ?? activity.id)
  }
  ```
  </TabItem>
  <TabItem value="ts" label="TypeScript">
  ```typescript
  const types = await client.activityTypes();
  const squats = types.find(t => t.displayName === "Squat Exercise")!;

  for await (const activity of client.activities.list({ activityType: squats })) {
    console.log(activity.name);
  }
  ```
  </TabItem>
  <TabItem value="python" label="Python">
  ```python
  types = client.activity_types.list()
  squats = next(t for t in types if t.display_name == "Squat Exercise")

  for activity in client.activities.list(activity_type=squats):
      print(activity.name)
  ```
  </TabItem>
</Tabs>

A type carries `id`, `name`, `slug` and `displayName`, and — when read from this list — `description` and `isCustom`.

Match on `slug` rather than on a name. It is derived from the name once and then stays put, so renaming a type leaves it alone, while `name` and `displayName` both follow the rename:

<Tabs groupId="language">
  <TabItem value="swift" label="Swift">
  ```swift
  let squats = try await client.activityTypes().first { $0.slug == "squat_exercise" }!
  ```
  </TabItem>
  <TabItem value="ts" label="TypeScript">
  ```typescript
  const squats = (await client.activityTypes()).find(t => t.slug === "squat_exercise")!;
  ```
  </TabItem>
  <TabItem value="python" label="Python">
  ```python
  squats = next(t for t in client.activity_types.list() if t.slug == "squat_exercise")
  ```
  </TabItem>
</Tabs>

The one already on an activity works as a filter too, so you can narrow to whatever you just saw:

<Tabs groupId="language">
  <TabItem value="swift" label="Swift">
  ```swift
  client.activities.list(activityType: activity.activityType!)
  ```
  </TabItem>
  <TabItem value="ts" label="TypeScript">
  ```typescript
  client.activities.list({ activityType: activity.activityType! });
  ```
  </TabItem>
  <TabItem value="python" label="Python">
  ```python
  client.activities.list(activity_type=activity.activity_type)
  ```
  </TabItem>
</Tabs>

## Sorting

Pass `orderBy` to choose the field, prefixed with `-` for descending. Swift takes a typed enum instead of a string.

<Tabs groupId="language">
  <TabItem value="swift" label="Swift">
  ```swift
  client.activities.list(orderBy: .createdAtDescending)
  client.subjects.list(orderBy: .name)
  ```
  </TabItem>
  <TabItem value="ts" label="TypeScript">
  ```typescript
  client.activities.list({ orderBy: "-createdAt" });
  client.subjects.list({ orderBy: "name" });
  ```
  </TabItem>
  <TabItem value="python" label="Python">
  ```python
  client.activities.list(order_by="-created_at")
  client.subjects.list(order_by="name")
  ```
  </TabItem>
</Tabs>

| List | Sort by |
|---|---|
| Activities | `createdAt`, `status`, `createdBy`, `activityType` |
| Subjects | `name`, `createdAt`, `updatedAt` |
| Sessions | `name`, `createdAt` |
| Subject groups | `name` |

A field the list can't sort by is refused straight away, with an error naming the ones it accepts.

## Counting Matches

`total` is the number of items matching the filter, not the number you have read. It is available before you start iterating, and reading it does not consume any items.

<Tabs groupId="language">
  <TabItem value="swift" label="Swift">
  ```swift
  let activities = client.activities.list(tags: ["baseline"])
  print("\(try await activities.total) match")
  ```
  </TabItem>
  <TabItem value="ts" label="TypeScript">
  ```typescript
  const activities = client.activities.list({ tags: ["baseline"] });
  console.log(`${await activities.total} match`);
  ```
  </TabItem>
  <TabItem value="python" label="Python">
  ```python
  activities = client.activities.list(tags=["baseline"])
  print(f"{activities.total} match")
  ```
  </TabItem>
</Tabs>

## Collecting Everything

`all()` returns every remaining match as an array, continuing from wherever iteration stopped. Use `limit` to cap how many items a sequence yields in total.

<Tabs groupId="language">
  <TabItem value="swift" label="Swift">
  ```swift
  let recent = try await client.activities.list(orderBy: .createdAtDescending, limit: 20).all()
  ```
  </TabItem>
  <TabItem value="ts" label="TypeScript">
  ```typescript
  const recent = await client.activities.list({ orderBy: "-createdAt", limit: 20 }).all();
  ```
  </TabItem>
  <TabItem value="python" label="Python">
  ```python
  recent = client.activities.list(order_by="-created_at", limit=20).all()
  ```
  </TabItem>
</Tabs>

## Stopping Early

In TypeScript, call `close()` on a sequence you stop reading early. Reading one to the end does this for you. Swift and Python need no equivalent.

<Tabs groupId="language">
  <TabItem value="swift" label="Swift">
  ```swift
  for try await activity in client.activities.list() {
      if activity.status == "done" { break }
  }
  ```
  </TabItem>
  <TabItem value="ts" label="TypeScript">
  ```typescript
  const activities = client.activities.list();

  for await (const activity of activities) {
    if (activity.status === "done") break;
  }

  activities.close();
  ```
  </TabItem>
  <TabItem value="python" label="Python">
  ```python
  for activity in client.activities.list():
      if activity.status == "done":
          break
  ```
  </TabItem>
</Tabs>
